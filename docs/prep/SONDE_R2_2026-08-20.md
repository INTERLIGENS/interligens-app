## Le choix de conception qui porte tout le C4

**Le module pur ne contient pas une seule ligne `import`.** Il ne sait rien
faire d'autre qu'appeler la fonction `headObject` qu'on lui injecte. Il est
*structurellement* incapable de lire une colonne — ce n'est pas une promesse
dans un commentaire, c'est une propriété vérifiable à la lecture, et un test
l'assert :

```ts
expect(src).not.toMatch(/^\s*import\s/m);
for (const interdit of ["@aws-sdk", "PrismaClient", "@/lib/prisma", 'from "pg"', "process.env"])
  expect(src).not.toContain(interdit);
```

**Les deux rôles ne sont jamais confondus : le registre dit ce qui DEVRAIT
exister, R2 dit ce qui existe.** La requête SQL du runner ne prouve rien sur les
octets, et n'est pas censée le faire.

## Les trois verdicts, et pourquoi il y en a trois

```
OK       — j'ai regardé, tout est là, aucune règle destructive en vue.
INCIDENT — j'ai regardé, et j'ai trouvé quelque chose.
UNABLE   — je n'ai pas pu regarder. Ce n'est pas rassurant.
```

Le compteur nº 4 du watchdog n'avait que deux états, dont un seul visible : un
nombre. **`UNABLE` est le verdict qui manquait**, et c'est celui qui a coûté une
pièce.

## Le contrôle négatif intégré — le canari

Avant d'examiner la moindre clé attendue, la sonde interroge une clé qui **ne
doit jamais exister** :

```
reports/__sonde_canari__/objet-qui-ne-doit-jamais-exister.probe
```

- **404** → R2 répond de façon autoritaire. Les 404 des vraies clés veulent donc
  dire « absent ».
- **autre chose** → on n'interprète **aucun** 404, et on s'arrête là.

**C'est le cœur du fail-closed.** Si un jeton était révoqué, R2 rendrait 403 sur
les 32 clés ; sans canari, la sonde annoncerait la destruction de 32 pièces
intactes. Avec canari, elle dit qu'elle n'a pas pu regarder. Mesuré en vif :
**un seul appel réseau avant l'arrêt.**

# LES DEUX OBSERVATIONS

## A — Les objets attendus

`HeadObject` sur chaque clé du registre. Un objet attendu devenu inaccessible
est un **INCIDENT**, pas un avertissement.

**Et la distinction qui décide de tout** — `classifyHeadError` :

| réponse R2 | classement | conséquence |
|---|---|---|
| `404` / `NotFound` / `NoSuchKey` | **absent** | fait observé → INCIDENT |
| `403`, `5xx`, DNS, TLS, timeout, tout le reste | **illisible** | non-observation → UNABLE |

Les confondre dans un sens annonce une destruction qui n'a pas eu lieu ; dans
l'autre, ramène le 0 rassurant. La sonde ne fait ni l'un ni l'autre.

## B — Le retour d'une règle destructive

`x-amz-expiration` n'est pas une échéance inscrite sur l'objet : **c'est une
valeur recalculée à chaque requête depuis les règles en vigueur à cet instant.**
Un objet sous `reports/` qui recommence à la porter = une règle destructive est
revenue.

**Ligne de base mesurée aujourd'hui : 0 en-tête sur 33 objets** — et **0 sur
1 103** en périmètre `--all`. Toute valeur > 0 est un incident.

Aucun credential d'administration n'est requis :
`GetBucketLifecycleConfiguration` rend `AccessDenied` et le Bucket Lock R2 n'a
aucune API S3. **Cette observation regarde le stockage lui-même, pas une
déclaration.**

## Tu m'as demandé de dire si ce proxy est faux. Il ne l'est pas — mais il a quatre limites, et je les nomme

**L1 — il n'observe que les clés qu'on lui donne.** Une règle destructive posée
sur un préfixe non observé lui est invisible. C'est pourquoi le runner **déclare
toujours son périmètre non couvert** au lieu de le taire :

```
⚠️  HORS PÉRIMÈTRE : 1071 ligne(s) du registre non observée(s)
```

**L2 — B détecte des RÈGLES, pas des suppressions.** Une suppression manuelle
par quelqu'un qui détient les identifiants ne se voit que par l'observation A —
donc **après** la perte. Aucune des deux n'empêche quoi que ce soit ; elles
constatent.

**L3 — B dépend de Cloudflare pour continuer d'émettre l'en-tête.** S'ils
cessaient, B lirait 0 en silence : exactement le défaut qu'on répare.
**Non auto-validante, et non validable** sans créer une règle destructive.
C'est le seul point de la sonde qui reste indémontrable, par quiconque, sans
provoquer le sinistre.

**L4 — B n'avertit que pour les objets pas encore échus** — voir l'encadré en
tête de ce document. C'est la limite structurante, pas une note : une règle
recréée détruit les pièces déjà échues avant le premier passage, et aucune
cadence ne rattrape ce cas.

1. **Le runner interroge la base via Prisma, pas `pg`.** `pg` n'a pas de types
