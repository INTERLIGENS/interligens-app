## 1. La vacance, reproduite avant d'être corrigée

Les trois tests du bloc 3 choisissaient leur source ainsi :

```ts
const ROUTE = "src/app/api/admin/osint/commit/route.ts";
const PATCH = "docs/prep/patches/B3-src-app-api-admin-osint-commit-route.ts.patch";
const tree  = fs.readFileSync(path.join(process.cwd(), ROUTE), "utf8");
const src   = tree.includes("orphanEvidenceItemIds") ? tree
            : fs.readFileSync(path.join(process.cwd(), PATCH), "utf8");
```

`src/app/api/**` est gelé par `scripts/guard-offline.sh` : le correctif a été
écrit, vérifié, **puis retiré de l'arbre**. La condition `tree.includes(...)` est
donc **toujours fausse**, et `src` vaut **toujours le fichier `.patch`**. Les
trois `expect(src).toMatch(...)` affirmaient que le patch contient ce que son
auteur y a écrit. Tautologie complète.

**Reproduit ce jour**, mutation `ok = true ||` posée dans la **vraie** route :

```
### ANCIENS TESTS sous mutation `ok = true ||`
 Test Files  1 passed (1)
      Tests  15 passed (15)      ← la route est cassée, tout est vert
```

Le second défaut est plus discret et **survivrait même si le correctif entrait
dans l'arbre** : ces assertions sont **textuelles**. `expect(src).toMatch(/status:
ok \? 200 : 207/)` est un `grep`, pas un test. `const ok = true;` suivi de
`status: ok ? 200 : 207` satisfait le motif **et** casse la route. Rediriger les
tests vers l'arbre au lieu du patch n'aurait donc corrigé que la moitié du
problème.
